# Codenotch 额度逻辑对齐记录

2026-09-19。用户要求额度读取、提醒和重置时间按 Codenotch 一致实现。本记录覆盖并替代 AI-Spec.md、AI-Implementation.md 和早期验收记录中的自定义额度策略；猫咪动画与任务识别仍由奶灰负责。

## 固定基线

Codenotch 最新发布版 v1.14.0，提交 c5b40a00c9c7df99acaeac0e6c9af49a452f4dda。通过 GitHub release API 核对。复用的模块及许可证见 THIRD_PARTY_NOTICES.md。以后上游升级不会自动改变本应用行为。

## 已接入

- Codex：本机 auth.json（支持 CODEX_HOME）读取登录，每次重新读取以跟上轮换；wham/usage 请求与上游一致，直接复用 CodexUsage 解析主额度、周期长度、Spark 和代码审查额度。月额度按服务端周期命名，不假设主额度必然为 5 小时。
- Claude：同组织 Desktop usage 缓存 → CLI /usage → OAuth。Desktop 最新匹配缓存 30 分钟内可用；扫描失败与 CLI 尝试间隔 5 分钟；已过重置时间的缓存不复用。OAuth 401/403 重新读凭证并重试一次；429 从 60 秒递增至 15 分钟并保存截止时间，不阻断前两种来源。三路使用同一 UsageResponse / LimitWindow 定义。
- 登录续期：使用 Codenotch 的 ClaudeTokenRefresher，由 standalone Claude CLI 空输入启动负责续期；本应用不自行发送 refresh-token 请求或写入凭证。结果按登录到期时间是否延长判断，同一到期时间失败后不循环重试；续期辅助进程不触发任务动作。
- 提醒：直接复用 ThresholdNotifier、UsageResetWatcher、UsageLimitWatcher。主窗口已用 80% / 100% 提醒；初次读取达到阈值也提醒；从低位跳到 100% 保留两次跨越；回落到 80% 以下重新允许提醒；周窗口有耗尽提醒。观察状态与上游一样保存在进程内，不沿用旧版本的持久去重规则。
- 重置：日期向后变化，或上游定义的显著下降，结合历史峰值检测；去掉旧版的“必须跨固定周期且二次确认”规则。
- 时间：直接复用 ResetCopy；默认自动日期，可切为倒计时。分钟使用四舍五入、时区和跨年按上游处理。
- 刷新：活动中 60 秒、空闲 5 分钟，到期后按 60 秒继续核对；正常短暂错误保留最近有效数据，超过 15 分钟标记过期。

## 集成边界

横版卡片、中文文案、猫咪气泡、动作和免打扰设置属于奶灰。提醒判定用上游模块，通知的呈现位置仍是奶灰，声音和系统通知依用户开关。连接权限通过明确入口申请，不静默触发钥匙串弹窗。本轮连接的是两家默认本机账号，不包含 Codenotch 全部多账号界面、兑换重置券、用量统计图或 Phone Link。

## 验证

- 对齐测试先验证旧实现失败：首次已用 85% 应提醒、Codex 跳过不可读窗口、Claude 连接优先无钥匙串来源。
- 7 组 AI 测试通过：压缩缓存解码与组织隔离、三路顺序、独立限流、跨年/时区、登录续期结果、通知阈值和重置、服务连接断开、会话回归。
- 原桌宠 29 项回归通过；发布构建及严格签名验证通过。
- 实机：已退出演示模式，两家成功连接。Codex 显示剩余 11%，与 Codex 自身额度工具的已用 89% / 重置时间一致。Claude 实际走 CLI /usage，显示会话剩余 93%、每周剩余 41%，并提供两项重置时间。以上为验收时快照，后续使用会变化。
- Desktop 缓存与 OAuth fallback、真实低额度跨越及真实重置使用合成样本验证，本机本轮未等待真实周期耗尽/重置，也未强制切换已经成功的 Claude 来源。
